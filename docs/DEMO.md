# Демонстрация для интервью

Демонстрационные данные создаются в отдельной пустой базе. Существующие аккаунты и обращения скрипт не изменяет. Общего встроенного пароля нет: передайте свой пароль через stdin, как в команде создания сотрудника.

PowerShell:

```powershell
$env:DATABASE_PATH = 'relay.demo.sqlite'
Get-Content -Raw password-file | node src/demo.js
npm start
```

Пароль — 12–128 символов. Храните временный password-file вне репозитория. Не используйте пароль от реального аккаунта. Для обычного запуска удалите переменную DATABASE_PATH из окружения либо откройте новый терминал.

Клиент: `client@example.test`. Поддержка: `agent@example.test`. Оба используют переданный демонстрационный пароль. Все имена и обращения вымышленные.

Сценарий на 5 минут: войти клиентом, показать поиск и статусы; создать обращение и комментарий; выйти; войти сотрудником и изменить статус; показать, что поддержка видит обращение другого клиента, а первый клиент — только свои. Затем открыть тест изоляции доступа, объяснить серверную проверку customer_id и транзакцию аудита.

Скриншоты реального Chromium находятся в docs/screenshots. Проверка выполнена в изолированном CI, без управления пользовательским браузером; сценарий клиента и поддержки прошёл успешно.
