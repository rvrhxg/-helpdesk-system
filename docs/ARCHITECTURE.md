# Архитектура Relay

Браузер → same-origin HTTP/JSON → проверка сессии и прав → параметризованные SQL-запросы → SQLite. Статические файлы выдаёт тот же сервер; отдельный CORS-сервис не нужен. UI написан на нативном JavaScript: DOM обновляется через `textContent`, пользовательский HTML не интерпретируется.

`src/server.js` содержит маршруты и HTTP-проверки, `database.js` — схему, `security.js` — криптографические функции. Для текущего размера это простой модульный монолит. По мере роста следует выделить сервисы авторизации/обращений и репозитории доступа к данным, добавить версионированные миграции.

Связи: пользователь создаёт много обращений, обращение содержит много комментариев; автор комментария — пользователь. Сессия хранит хеш токена и срок действия. Смена статуса и запись аудита выполняются в одной транзакции: либо сохраняются обе операции, либо ни одна.

Почему cookie? HttpOnly уменьшает доступ JavaScript к токену, SameSite=Strict и точная проверка Origin защищают изменяющие запросы от межсайтовой отправки. Для HTTPS включается Secure. Ограничения доступа проверяются сервером при каждом запросе; скрытой кнопки в UI недостаточно. Чужое обращение возвращает 404, чтобы не раскрывать его существование.

Почему SQLite? Бесплатный запуск без внешней инфраструктуры, внешние ключи и транзакции, удобная демонстрация. Один файл и ограниченная параллельная запись затрудняют горизонтальное масштабирование; следующий шаг — PostgreSQL и миграции. WAL улучшает совместимость чтения и записи, но не превращает SQLite в распределённую базу.

Практика: самостоятельно добавьте новый статус с изменением CHECK-ограничения и миграцией, пагинацию API или тест на истёкшую сессию. Не называйте проект коммерческим и не заявляйте технологии, которые не сможете показать в коде.
